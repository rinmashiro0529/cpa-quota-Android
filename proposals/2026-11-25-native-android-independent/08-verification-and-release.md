# 08 · 验证体系与完整发布门禁

本章是未来实现的验证合同。此次仅完成源码审阅、方案编写与文档一致性检查；没有执行 Android 构建、模拟器、真机、数据库迁移、真实推理、FCM 或 Go 服务升级。既有源 CI 记录见 [02](02-source-parity.md)。

## 1. “完美”落实为可核验标准

产品质量由完整范围、正确行为、数据可恢复、系统适配、隐私、性能和可维护性共同决定。任何一项缺失都不能由漂亮 UI 或绿色单元测试抵消。发布声明必须指向准确的源基线、Android 提交、服务提交、二进制摘要与设备矩阵。

- 所有 93 项必需能力都有对应实现和真实验收记录；4 项增强单独列示。
- 所有必需工作项已 verified。TASK-033 由发布审阅者核对其他33项和最终证据后关闭，不能自证循环。
- 未执行、环境不支持、结果不可复现、模拟返回，均不能记为 pass。
- 固定源码、实际实现、实际运行证据发生漂移时，重新验证受影响门禁。
- 严重或高风险问题未解决则发布阻断，不用“后续优化”掩盖数据丢失、重复计费或凭据泄露。

## 3. 必须使用故障与竞争条件测试

### 3.1 请求、身份与计费

给每个可产生结果的操作安排唯一ID和受控完成屏障，覆盖：旧连接最后完成、新连接先完成；取消与最后一帧同时到达；删除与完成竞争；token旧回调在新revision之后到达。断言旧结果既不更新UI也不落库，外部请求计数符合合同。

聊天POST测试必须观察发送次数。EOF、200坏body、半条输出后断线、后台回收均不得触发透明重发。允许的协议兼容回退单独测试准入条件和最大次数，不能让通用HTTP重试器参与计费动作。

### 3.2 持久化与恢复

在附件复制、改名、数据库引用、消息checkpoint、终态提交、取消记录和秘密删除之间注入故障。重启后验证无悬空可见附件、无已删内容复活、无静默明文回退。读取失败时保留可恢复事实，不把失败当成空库覆盖。

Activity recreation、普通系统进程回收、用户force-stop三者分别取证；它们的后台行为不同。force-stop后不承诺继续投递或任务自动运行。

### 3.3 安全预览

静态HTML负例覆盖script、事件属性、CSS加载、iframe、重定向、下载、file/content/intent、JS bridge和弹窗。使用loopback测试服务做“允许联网正对照”，再证明被测隔离预览访问不到；否则设备断网可能造成假通过。预览功能本身必须可用，不能通过关闭入口规避等价要求。

## 4. 最小验收环境

准确型号与系统build在实施时填入，未提供真实硬件前保持blocked。下表是覆盖要求，不声称已经拥有或测试这些设备。

| 维度 | 首版至少覆盖 |
| --- | --- |
| 系统下限 | API26安装/主要路径/存储恢复；可用模拟器做回归，支持声明须按06补真实设备抽查 |
| 当前目标系统 | API37模拟器及真实设备；验证LAN、返回/窗口、通知和系统展示 |
| 兼容行为变化 | API33通知；API35/36窗口、edge-to-edge及后台变化，按场景分层覆盖 |
| 厂商与形态 | 至少两个具GMS厂商的手机；平板或折叠屏真实窗口变化；精确型号记录 |
| 无GMS | 至少一个被声明支持的无GMS环境，验证透明降级与完整本地聊天能力 |
| 网络 | 公网、反向代理前缀、局域网、切网、断网、TLS失败、延迟和429 |
| 权限 | 首次允许/拒绝、设置撤销、通知channel关闭、照片单项授权、LAN拒绝 |
| 用户设置 | 系统/明暗主题，200%文字，TalkBack，减少动画，中文/英文或项目明确支持的locale |
| 数据 | 空库、长会话、多会话、多账号、4图单轮、坏附件、旧schema、低存储 |

FCM验收必须从新服务发出，经真实provider与获授权设备接收，校验当前订阅revision、过期过滤、去重、冷启动路由和停止之后的行为。仅HTTP成功或控制台显示accepted不证明设备展示。

本表不降低06的DEV-E/DEV-G要求：声明支持折叠或双屏形态时须有对应真机，平板或模拟器不能替代其铰链与窗口行为证据；无GMS核心能力与降级也须在代表性真机补证。缺少硬件时相关声明保持未验证，不将环境缺失记为通过。

## 5. 性能预算与测量合同

性能目标是本候选的工程验收建议，**不是已测结果**。TASK-002选择渲染与工具链；TASK-008建立基准；TASK-030用同一Release配置与参考设备复测。预算如需变更，必须在测量前记录原因、设备与用户影响，不能失败后删掉门禁。

| 项目 | 初始目标与边界 |
| --- | --- |
| 冷启动 | 已配置、持久数据在本机时，参考中端真机首个可交互工作区 p95 ≤ 2秒；网络完成不算启动前置 |
| 长列表与流式滚动 | 固定60Hz参考环境的标准滚动脚本卡顿帧比例 < 5%；同时报告时长和帧数，其他刷新率另列 |
| 用户停止 | 受控网络下stop到客户端流停止/资源释放 p95 ≤ 500ms；不据此保证远端服务停止计费 |
| 账号读取 | 合成1/10/50账号，首个可用结果逐步发布，不等待最慢账号；并发上限保持合同 |
| 聊天数据 | 1,000会话/10,000消息的合成档案，列表、包含搜索和进入详情不解码全部附件 |
| 图片/内存 | 单轮4张约定上限图片与连续20轮打开关闭，无OOM；附解码峰值与回收曲线，不只看一次RSS |
| 磁盘写入 | 按有界checkpoint批次提交，不每token重写全历史；记录写入次数、字节和恢复丢失窗口 |
| 请求与通知 | 取消后无持续读取；重复事件不重复展示；后台无无界轮询、无无意义保活 |

使用Macrobenchmark/帧与内存跟踪等实际工具，保留命令、设备温度/电量条件和采样方法。Debug/模拟器数据用于诊断，不能替代Release真机结论。首次20–50轮测量确定样本稳定性；不能挑最好一次当p95。

模型出字时间、搜索服务延迟和FCM服务投递延迟单独报告，不混成客户端性能。性能改善不得通过取消安全校验、缩减渲染能力或丢弃消息获得。

## 6. 发布门禁

| 门禁 | 必须提供 | 阻断示例 |
| --- | --- | --- |
| G0 企划一致性 | 文档validator通过、来源和任务可追踪 | ID缺失、依赖环、生成索引陈旧 |
| G1 工程与合同 | 实际版本锁、构建/安装、规范fixtures | SDK示例无法构建、关键源差异未裁定 |
| G2 业务完整性 | 全部五工作区、93必需能力逐项证据 | 聊天只做发消息、CAP缺请求明细、监控占位 |
| G3 数据与安全 | 迁移/低存储/缺钥/删除/HTML/计费失败测试 | 数据丢失、秘密外泄、重复自动POST |
| G4 平台与服务 | 声明设备矩阵、真实FCM、v1兼容、停止恢复 | 模拟推送充数、无GMS虚报全能力 |
| G5 Release质量 | 最终优化包的性能/无障碍/原生UI证据 | 只测Debug、宽屏遗漏、关键操作TalkBack不可达 |
| G6 分发与运维 | 签名覆盖升级、隐私、服务版本、故障手册 | 签名不连续、数据库降级破坏、无停止/恢复方法 |
| G7 完整审定 | 精确SHA与产物摘要、来源漂移、独立审阅、发布授权 | 非最终提交的绿灯、未执行check算通过、未授权发布 |

必需CI job应同时验证存在、执行完成且成功，skipped/neutral/缺失不视为pass。对依赖硬件/签名/外部服务的人工门禁单独维护证据，不伪装成每PR都能自动运行。分支保护或required-check设置如未配置，应写为待配置事项，不声称仓库已有保护。

## 7. 证据与缺陷分级

每份证据至少包含：能力/任务ID、实现仓库与commit、源SHA、服务commit与合同版本、实际命令或操作步骤、环境和设备、预期与结果、pass/fail/blocked/not_run、日志/截图/trace位置及摘要、测试时间、实现者、独立审阅者。结构见 [evidence-template.json](manifests/evidence-template.json)。

- P0：凭据泄露、跨身份访问、大范围不可恢复数据丢失；立即阻断相关交付与发布。
- P1：完整必需功能缺失、重复计费风险、停止/删除失效、关键系统下不可用；完整发布阻断。
- P2：有明确可用路径的局部缺陷；写清影响、修复版本和接受责任，不能涉及必需能力的验收失败。
- P3：非阻断的视觉细节和基线外优化；独立积压，不冒称无缺陷。

风险接受不能把failed证据改为passed。要调整产品范围，只能修订明确的支持声明与能力合同，并重新审查“完整移植”称谓。

## 8. 最终交付与回退

交付可重建源代码、Release AAB/APK摘要、版本矩阵、数据schema历史、能力和证据索引、兼容服务版本、安装/升级步骤、隐私与删除说明、故障恢复手册、已知限制。

客户端数据库升级默认前向迁移；发布前备好前向修复策略。旧APK若不能读新schema，不承诺直接降级回滚。服务回退必须遵守v1/v2持久格式兼容和永久取消语义，不能靠删除墓碑恢复旧状态。签名、生产密钥、服务部署和商店发布分别按实际授权执行，企划被选定不自动等于授权所有生产动作。
