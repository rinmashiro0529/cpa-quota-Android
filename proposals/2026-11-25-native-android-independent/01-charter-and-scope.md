# 01 · 项目目标、意图与范围

状态：独立候选，用户尚未选择。来源固定为 [iOS 80beea9](https://github.com/rinmashiro0529/cpa-quota-ios/tree/80beea9ed251a628307825cba99290b5f246575b)。本章的要求在候选被采用后成为项目默认，后续变化通过版本化决策记录管理。

## 1. 用户意图与交付定义

用户需要一份可供不同开发者和 agent 接手的启动基准，目标是完整移植 iOS 版本到原生 Android。方案应能回答“做哪些功能、如何划分职责、哪些行为不能改变、先做什么、何时算完成”，并让实施者无需猜测关键安全和数据语义。

本次已获授权的产物是独立企划及其 GitHub 提交。App、后端升级、签名、推送账号、真实 CPA 接入、商店发布和生产部署属于实施阶段；本文不把这些活动记为已执行。

最终交付包含：

- 原生 Kotlin/Compose 应用源码、可重建构建配置和签名分发流程。
- 五工作区与完整功能矩阵的全部必需能力。
- Android 系统替代：安全凭据、原生通知、小组件、折叠屏/大屏、剪贴板、系统图片选择及必要的安全文件交互、进程恢复。
- Android 可用的监控协议与服务端投递支持，以及现有 iOS 客户端兼容证据。
- 运行时验证、真实设备记录、协议 fixtures、数据库迁移和升级证据。
- 运维/隐私/故障恢复说明和后续维护方法。

## 2. 完整性有三个维度

### 2.1 功能等价

源端可达的入口和操作均应映射到 Android：五导航栈、连接与记住/临时模式、额度查询和筛选、CAP 四栏目及明细、诊断、完整聊天、监控诊断恢复、系统展示。详见 [02](02-source-parity.md)。

### 2.2 行为等价

失败、取消、迟到响应、持久化失败、限流、账号身份变化和跨服务历史发送，与成功流程同属必需范围。用户看到相同数值但实际请求、隐私或恢复行为不同，不算行为对齐。

### 2.3 平台等价

Apple 特有 API 映射为 Android 支持的用户能力，明确替代形式及边界。ActivityKit 的视觉形态不作为 Android 像素目标；监控状态、用户控制、更新隐私、停止与恢复仍需交付。每项映射要有本机验证，不用 iOS 模拟器截图、单纯 UI mock 或接口占位证明。

## 3. 支持设备与能力声明

候选默认 minSdk 26、compileSdk/targetSdk 37。它们是工程预研输入；TASK-002 必须锁定能真实构建与运行的完整工具链组合。

| 环境 | 首个完整版本的承诺 |
| --- | --- |
| 声明支持的 Android 手机/平板/折叠屏，具兼容 GMS、通知授权及可用新监控服务 | 全部源功能的 Android 等价；推送与小组件需真实验收 |
| 无 GMS 或 FCM 不可用 | 连接、额度、CAP、诊断、完整聊天（含有界后台收尾及获授权的本地完成通知）、监控控制/查询等可用；监控周期更新尽力而为；必须明确监控远端推送能力缺口，不能宣传该设备推送全等价 |
| 通知权限被拒绝或 channel 关闭 | 核心功能与保存可用，通知能力受限，状态解释与恢复入口可用 |
| 只运行旧监控服务 | 能力发现明确升级需求；可兼容的旧会话查询/停止保持；不得伪造新 Android 订阅已生效 |
| 无网络/系统回收 | 已持久数据可恢复，未完成操作标为中断或待核对；不自动重放可能已产生费用的聊天 |

完整性结论必须附支持矩阵，不能把对已认证设备的结论扩张成所有 Android 设备。若用户选定的发行范围要求某类无 GMS 设备也具完整实时投递，ENH-03 在开工范围确认时转为该发行版的必需项，并增加实际 provider 和真机证据；不能只修改宣称。

## 4. 五工作区与业务边界

- 额度：已有账号、渐进读取、多个窗口/指标/credits、状态筛选与单账号详情。
- CAP：模型概览、趋势/分组/费用、请求记录、管理统计，以及显式权限模式与范围。
- AI 对话：完整模型/Key 管理、双协议、reasoning、图片、消息操作、续写、搜索、记忆、技能、富文本/HTML、存储及后台收尾。
- 账号诊断：连接、可选能力、各账号读取和错误层次。
- 连接：CPA 与独立监控服务、偏好、隐私、小组件共享。监控保留在此工作区的内部导航。

管理功能维持只读定位，不新增上游 OAuth、改配置、启用账号或重置额度。AI 对话和联网搜索会调用外部推理/检索服务，必须保持各自密钥、传输目的地和潜在费用边界。

## 5. 首版的明确选择

1. Android 在用户指定的独立仓库根构建，不沿用上一轮讨论中的同仓 Android/ 子目录。
2. Kotlin 承担客户端业务，Compose 为主 UI；协议和规则以纯 Kotlin 保持可测。
3. Room 保存聊天/草稿/操作记录，附件为私有文件；密钥由独立 SecretStore 处理。
4. 额度/CAP 默认延续会话内快照；新增磁盘缓存须另立数据保留与隐私决定。小组件只保存用户已允许共享的最小投影。
5. 用有界状态机、显式身份和持久化恢复控制并发，不依赖页面销毁或延时猜测。
6. 聊天后台与源端的最多约 30 秒尽力收尾对齐；不承诺保活到 30 秒，不强制新增跨进程聊天服务器。
7. Go 监控源码仍由 iOS 仓库对应服务目录维护，新能力以独立服务 PR 交付，不复制成两个长期分叉服务。
8. 最终发布要完成监控和系统展示；不得把这两项无限推迟后仍称完全移植。

## 6. 基线外增强

ENH-01 跨端导入导出、ENH-02 跨进程持久聊天、ENH-03 指定无 GMS 实时通道、ENH-04 云同步均单独记录。它们不是源端当前已证明的全部能力，也不会暗中扩大默认交付。Android 的持久草稿、数据库迁移和附件外置是实现质量选择，不意味着新增云服务或自动外传数据。

## 7. 决策权与变更

本方案是候选。用户选择之后，技术细节可由负责人按既定约束自主完成，禁止把常规实现决定都上升为反复询问用户。涉及功能范围、外部目的地、凭据策略、不可逆数据迁移、生产部署、额外费用和公开发布的实质变化，应依照当前会话授权与项目流程处理。

对源端行为发现缺陷时：保留证据 → 写差异决定 → 制作修复预期 fixture → 在 Android 实现 → 向原服务/客户端提出独立修复。既不盲目复制已识别缺陷，也不能悄悄把新行为称为原样移植。

## 8. 完成标准

所有 release_required 能力有实现责任、确定性验收和运行证据；所有必需任务已 verified；正式版本的数据升级、签名安装、声明支持设备、服务版本与通知链路已核对。未完成项清楚保持 blocked。没有“百分之百没有缺陷”的承诺，只有可复核的范围和证据。
