# 06 — Android 平台适配、生命周期与安全

> 状态：独立候选企划，待选择；本文件提出实施合同与验收要求，不表示功能已实现或设备测试已通过。  
> 官方资料核查日期：2026-11-25（北京时间）。  
> 对应候选目录：`proposals/2026-11-25-native-android-independent`。

本章的目标是让相同的产品能力在真实 Android 手机上成立：连接凭据得到保护，五个工作区拥有独立导航，聊天不会因旋转或切页重复发送，退后台与进程死亡有确定的恢复行为，监控与小组件诚实呈现数据新鲜度和通知能力。

职责边界如下：模块与身份定义见 [03-architecture.md](03-architecture.md)；请求、会话与监控协议见 [04-protocols-and-monitoring.md](04-protocols-and-monitoring.md)；聊天状态机、附件与持久化见 [05-chat-and-storage.md](05-chat-and-storage.md)；测试证据、签名及发行门禁见 [08-verification-and-release.md](08-verification-and-release.md)。本章补充 Android 特有约束，不另建第二套业务状态机或身份体系。

跨章节能力与交付统一使用 [feature-parity.json](manifests/feature-parity.json) 的能力 ID 和 [work-items.json](manifests/work-items.json) 的 `TASK-*`。本章 `PLAT-S*` 是已分派任务内部的验证包，`PLAT-CASE-*` 是局部场景编号，均不新增一套独立发布范围；具体任务映射见第 11 节。

## 1. 技术基线与版本核查

### 1.1 候选技术决策

| 项目 | 候选决策 | 选择理由与约束 |
| --- | --- | --- |
| 客户端语言 | Kotlin | Android 平台适配使用原生 API；协议解析与业务规则尽量保留为可单独测试的纯 Kotlin |
| 主界面 | Jetpack Compose + Material 3 | 五个工作区、聊天、设置和导航均由原生界面实现 |
| 导航 | Navigation 3 稳定版本 | 用显式、可保存的返回栈表达工作区与详情，不用 URL 字符串承载整份业务对象 |
| 自适应布局 | Material 3 Adaptive + WindowManager | 根据实际窗口、铰链和输入法布局；不以设备营销名称判断单双栏 |
| UI 状态 | ViewModel + 不可变状态 + StateFlow | UI 发出用户动作，状态持有者处理动作；网络任务与页面收集生命周期分开 |
| 结构化持久数据 | Room | 聊天、草稿、附件索引与操作记录按第五章执行；数据库 schema 从首版起版本化 |
| 偏好与秘密 | DataStore 保存非秘密设置；SecretStore 保存加密凭据 | 不把普通 Room/DataStore 实例当作“已加密”的证据 |
| 后台补偿 | WorkManager | 仅承担可延迟、可重试、可被中止的有限任务 |
| 通知 | Android 通知；FCM 为可选传输实现 | 通知权限、推送可用性和监控订阅分别建模，无 GMS 设备保留核心功能 |

这些是本候选方案的工程选择。Android 官方架构建议支持 Compose、单向数据流、ViewModel 和随生命周期收集状态，但不要求将每个 getter 都包装成 use case，也不要求为每个接口单建 Gradle 模块。[S01]

### 1.2 SDK 的三个数字分别决策

候选基线为 **`minSdk = 26`、`compileSdk = 37`、`targetSdk = 37`**。

- `minSdk 26` 是本项目支持范围建议，不是 Android 官方对所有应用的统一最低要求。第一阶段需用依赖解析和低版本启动结果证明所有依赖支持它。
- `compileSdk 37` 用于编译 Android 17 API；实际调用新 API 仍须按运行系统版本保护。
- `targetSdk 37` 主动采用 Android 17 的平台行为，尤其是局域网权限、大屏适配与小组件内存约束。[S04][S06]
- 2026-11-25 核查的 Google Play 政策要求普通新应用和更新至少 target API 36，生效日期为 2026-08-31。这是提交底线，不等于推荐永远停留在 36。发行前仍须再次核查当期政策。[S05]

### 1.3 已核实的稳定版本与尚未证明的兼容组合

| 官方资料 | 本次核查结果 | 本项目如何使用 |
| --- | --- | --- |
| Navigation 3 release 表 | Stable 栏为 `1.2.2`；同页依赖示例展示 `1.3.0-alpha05` | `1.2.2` 是候选验证版本；不复制示例中的 alpha |
| Material 3 Adaptive release 表 | Stable 栏为 `1.3.0`；示例展示 `1.4.0-alpha03`；1.3.0 发布说明包含 `adaptive-navigation3` | 将稳定 Adaptive 与稳定 Nav3 的组合放入工具链验证 |
| Android 17 SDK 设置页 | 明确写 `compileSdk/targetSdk = 37`，同时保留 Preview 安装措辞和旧 AGP RC 版本提示 | API 级别有官方支持；最低工具链组合不能只凭这一页认定 |

上述差异已经观察到，不将它们解释为“稳定库不能使用”或“只能用预览工具链”。启动任务 **PLAT-S01** 必须产生一份实际验证过的版本矩阵：Android Studio、JDK、Gradle wrapper、AGP、Kotlin、Compose compiler/BOM、Navigation 3、Adaptive、WindowManager、Lifecycle、Room、WorkManager，以及可选 FCM 的确切版本与依赖来源。[S02][S03][S04]

PLAT-S01 的退出证据必须包含：干净环境依赖解析；debug 与压缩 release 构建；API 26 和 API 37 安装启动；五工作区最小导航；单双栏切换；进程重建；KSP/序列化/Room 代码生成；依赖树与选定版本。仅有 Android Studio 预览图或“同步 Gradle 成功”不够。若某个稳定组合无法工作，记录失败日志和最小复现，再决定降级其中一个库或替换局部适配方式；不得偷偷引入 alpha 使门禁变绿。

## 2. 五个独立导航栈与原生窗口适配

### 2.1 导航不变量

工作区名称与 `WorkspaceId` 由第三章统一定义。本章要求五个工作区各自拥有返回栈、当前选中条目、筛选状态和必要的滚动定位。

1. 切换工作区保留原栈，不把另一个工作区的详情页压入当前栈。
2. 路由 key 仅携带稳定 ID 和少量可序列化参数，不携带 API key、完整聊天记录、bitmap、附件字节或未受限 JSON。
3. 打开详情只改变导航和选中状态；实际网络请求由业务控制器根据业务动作启动。Composable 重组、列表项重新出现和窗口宽度变化均不能再次提交请求。
4. 同一个会话的 UI 可在单栏与双栏间移动，业务 ID 和流式任务 ID 保持不变。
5. 通知或小组件深链先经过连接及授权校验，再定位到所属工作区和目标 ID。目标被删除时显示可恢复的空状态，不自动切换到另一个账户的同名对象。
6. 同一窗口的栈由窗口拥有。未来允许多窗口实例时，各窗口的导航不放进一个全局可变 singleton；共享的业务操作通过稳定 ID 合流。

推荐用 Navigation 3 的可保存返回栈与 entry 状态管理，再用稳定版 Adaptive 的 scene strategy 选择列表/详情或主内容/辅助内容场景。它们共同表达同一套业务目的地；不维护一套“手机版导航”和另一套“平板版导航”。具体 API 与默认返回行为通过 PLAT-S01 固定。[S02][S03]

| 用户动作 | 候选行为 | 必须保持 |
| --- | --- | --- |
| 切至另一个工作区，再切回 | 恢复原栈顶和选中条目 | 草稿、正在进行的会话、筛选条件 |
| 重复点击当前工作区入口 | 默认保留当前位置；若设计支持回根页，必须为显式一致的交互 | 不隐式丢弃草稿或取消生成 |
| 紧凑窗口打开详情 | 单栏进入详情 | 返回后恢复原列表定位 |
| 详情展开为双栏 | 同时展示原列表和选中详情 | 不重新创建生成操作 |
| 双栏缩为单栏 | 优先显示当前已选详情 | 返回语义与单栏一致 |
| 通知跳转到已删除或已解绑对象 | 展示“内容不可用/需要重新连接”及安全入口 | 不显示旧账户秘密，不自动重发操作 |
| 完成或取消返回手势 | 完成才提交导航状态变化；取消保持原状 | 不在手势中途发出删除、发送、切账号等业务动作 |

### 2.2 按窗口与铰链布局

使用实际窗口尺寸等级和 `FoldingFeature` 进行布局。`bounds`、`isSeparating`、`occlusionType` 反映铰链或折痕对当前窗口的影响；不能假定“双屏”只等于屏幕足够宽，也不能依赖精确铰链角度。[S08]

| 场景 | 布局要求 |
| --- | --- |
| 紧凑手机窗口 | 单栏内容和适合窄屏的主导航；表格转为可阅读的卡片或带表头的横向区域 |
| 宽屏/平板 | 导航 rail 与列表/详情；给正文、表单和聊天设置合理阅读宽度 |
| 纵向分离铰链 | 将两栏分别放入可用区域，发送按钮、选中项、图表关键值不可被铰链切开 |
| 横向半折叠 | 依据可用高度安排主内容与操作；输入法出现时仍可见输入框及发送/停止按钮 |
| 分屏/桌面窗口 | 连续缩放不中断业务；不锁定纵向逃避适配 |
| 外接键盘/鼠标 | 可见焦点、合理 Tab 顺序、快捷键不与输入法组合输入冲突 |

API 36/37 的大屏行为已趋向强制自适应，target 37 不能依靠 API 36 的临时限制缩放豁免作为方案。必须从骨架阶段处理大屏与旋转。[S06][S07]

### 2.3 IME、edge-to-edge 与返回手势

- 统一管理系统栏、显示缺口和 IME insets；明确每层是否已经消费 padding，避免 Scaffold 与输入框重复叠加留白。[S09]
- 聊天输入区随 IME 移动；切换输入法、显示表情键盘、横屏和折叠后，光标与未提交的组合文本不会变成一次“发送”。
- 使用受支持的返回处理 API。输入法、弹窗、页面栈和退出的优先级需要实测，不在根页面无条件拦截所有返回事件。[S07]
- 可见面板变化不能改变用户焦点到不相关的工作区；TalkBack 顺序与视觉阅读顺序一致。
- “停止生成”和“返回上一页”是不同动作。用户返回列表时不隐式创建新请求，也不以屏幕关闭来证明生成已经停止。

## 3. 生命周期、流式任务所有权与恢复

### 3.1 所有权划分

| 对象 | 所有者与生命周期 | 禁止的隐式行为 |
| --- | --- | --- |
| 页面 UI 状态 | 对应导航 entry 的 ViewModel | 旋转时重复发起写请求；持有 Activity/Window 等 UI 引用 |
| 网络流式生成 | 会话级 coordinator；按会话 ID、连接身份与生成 ID 索引 | 绑定某个 Composable collector 的存在；多个页面各创建一条流 |
| 请求身份 | 操作创建时捕获的不可变身份及凭据版本 | 读取后来变化的全局“当前账号”给旧请求补 Authorization |
| 本地消息、草稿、附件引用 | 第五章定义的持久层 | 仅存在 ViewModel、返回栈 Bundle 或通知 extras 中 |
| 周期补偿任务 | WorkManager，按稳定业务身份命名的 unique work | 每次启动页面注册一份新任务；解绑后继续使用旧凭据 |
| 监控订阅 | 第四章定义的独立订阅身份 | 直接等同于聊天会话、当前 UI 连接或 FCM token |

UI 停止 `collectAsStateWithLifecycle` 只表示停止收集 UI 数据，不能由此推导网络已经停止。coordinator 必须拥有明确的取消入口、截止时间和最终落盘逻辑。取消传播到实际网络 call，不能仅把按钮改成“已停止”。

### 3.2 状态必须分成三个层次

| 状态 | 存储位置 | 恢复规则 |
| --- | --- | --- |
| 临时 UI 状态：工作区、选中 ID、筛选、少量滚动信息 | SavedStateHandle/可保存导航状态/rememberSaveable 等 | 用于系统重建；保存最小重建线索 |
| 用户数据：草稿、已接收消息片段、附件引用、操作状态 | Room 与应用私有文件 | 应用重启后从持久层重建；事务与文件一致性按第五章执行 |
| 活动资源：socket、coroutine、解码器、取消句柄 | 进程内 coordinator | 进程死亡后不存在；不能序列化后假装恢复同一条连接 |

ViewModel 能跨配置变化保留内存状态，不能跨进程死亡保存对象。Saved state 适合小数据，不代替数据库；用户从最近任务移除、force-stop 或重启等显式结束场景也不能依赖原 saved-state 记录仍存在。[S10]

### 3.3 聊天退后台：对齐现有约 30 秒有界尽力收尾

本候选按第五章的 iOS 基线核对结果，保留“进入后台后最多约 30 秒、系统可以更早终止”的能力边界。**不把这项能力扩写为进程死亡后继续生成，不以新增服务端持久聊天作业作为本次完整移植的前置要求。**

候选执行合同：

1. 同一生成跨聊天详情、工作区切换和单双栏变化仍由同一个 coordinator 管理；只要应用还有可见窗口，不因单个页面停止收集而进入后台收尾。
2. 检测到真实前台→后台转换时立即请求检查点，将已确认接收的片段、生成 ID 和当前状态尽快提交到持久层。流式过程中也要有有界检查点，不能把全部保存寄托在最后一次 `onStop/onDestroy`。
3. 同一次后台转换只产生一个收尾 deadline。进程仍可执行时尽力接收剩余结果，后台预算最多约 30 秒；重复生命周期回调不能延长这次 deadline。
4. 截止时间以单调时间判断，设备休眠后的下一次执行也必须检查是否已经过期。此设计限制应用行为，不代表系统会保证提供完整 30 秒 CPU 或网络时间。
5. 收尾期间提前完成：先提交完整结果，再在用户允许且通知通道可用时发送去重后的本地完成通知。
6. 到期：取消实际网络 call，保存已接收片段，记录明确的后台超时中断原因。不能把中断消息标成完整答案。
7. 期限内回前台：只有原操作仍在运行才继续观察它；已经停止的操作不得自动重新 POST。同一转换的陈旧 timeout 回调必须因 generation/background epoch 不匹配而失效。
8. 进程死亡：下次启动将没有活跃执行者的未结束本地操作归一为 `interrupted` 或第五章等价状态，展示已保存片段；不自动重发可能产生费用或重复答案的生成请求。

Android 无对应的“无条件授予 30 秒”平台承诺。**PLAT-S02** 必须在真实设备、Doze 和厂商后台策略下验证以上语义。spike 可证明尽力收尾能工作，也可以证明某些设备会更早中止；后者应形成诚实的设备能力说明和安全恢复证据，不能伪造统一成功率。

如确需前台服务实现某个用户明确发起的有限操作，先验证合法服务类型、启动条件、通知、停止入口和发行要求，再决定是否引入。不能把任意 SSE 贴上 `dataSync` 标签后宣称永续运行。Android 对部分前台服务存在时限；长运行 Worker 也会用前台服务，且 Android 16 起可能消耗 job 配额。[S26][S27]

服务端 durable task/status/cancel/result 协议可作为未来增强，届时另立 ADR、协议与发布范围。它不是这里约 30 秒基线的隐含替代品。

### 3.4 生命周期事件的可验收结果

| 事件 | 必须发生 | 不应声称 |
| --- | --- | --- |
| 旋转、语言/主题变化、窗口 resize | UI 重建后观察同一操作；草稿与身份保持 | “Activity 重建测试通过”等于“进程死亡恢复通过” |
| 切工作区或在双栏隐藏详情 | 保存导航状态；会话任务按明确策略继续 | collector 停止自动代表请求取消 |
| 全部窗口进入后台 | 立即检查点，进入上述有界尽力收尾 | 一定持续 30 秒，或一定完成 |
| 系统回收进程 | 下次启动读取持久数据，未完成操作显示中断 | 恢复原 socket、自动续传任意 SSE |
| 用户 force-stop | 不尝试绕过用户停止；下次主动打开安全恢复 | Worker、推送或接收器保证会唤醒应用 |
| 断网/网络切换 | 保存部分结果，按协议区分可重连读取和不可重放写入 | 所有超时都可安全重试 POST |
| 切换或删除连接身份 | 仅处理该身份域中受影响的操作、回调和任务；CPA 切换不清理独立监控的 detached handle，远端结果不明保留恢复记录 | 将旧流剩余 token 写进新身份会话，或把本机清理误报为远端停止 |

## 4. 权限按场景申请

权限不是安装后一次性索取的清单。每个入口在需要时申请，拒绝后保留可用功能；不把通知、局域网、图片选择合并成一个阻断启动的步骤。[S16][S17][S18]

| 场景 | 权限或平台机制 | 申请时机与范围 | 拒绝/撤销后的行为 |
| --- | --- | --- | --- |
| 普通远程 API 请求 | `INTERNET`；网络状态观察如使用则声明相应普通权限 | manifest；不弹运行时权限框 | 对实际失败分类，不能把所有错误归为“离线” |
| API 37 设备上 target 37 连接 LAN 或 `.local` 服务 | `ACCESS_LOCAL_NETWORK` | 用户连接需要局域网访问的服务时；不为公共互联网地址无差别索取 | 保留配置和缓存；明确提示局域网权限，可重试或改地址；不误报凭据无效 |
| API 36 及更低运行系统 | 不执行不存在的新权限请求 | 用版本判断隔离 API 37 行为 | 不向用户展示无效授权入口 |
| API 33+ 额度告警、完成通知 | `POST_NOTIFICATIONS`；通知 channel 状态 | 用户启用提醒时 | 应用内消息与数据继续可用；显示通知未获准，不循环弹窗 |
| 选择图片附件（CHA-06） | 系统 Photo Picker；不支持时使用受控系统选择器 | 只授权用户选中的项目；视频不因此自动进入基线 | 取消选择等同未添加；无需全媒体库权限 |
| 文档/配置导入，若相关增强被采用 | Storage Access Framework，`ACTION_OPEN_DOCUMENT` 等 | 只访问所选 URI；需要长期引用且 provider 允许时获取持久授权 | URI 失效显示重新选择；不通过扫描整个存储补救 |
| 保存导出文件，若相应功能被采用 | `ACTION_CREATE_DOCUMENT` | 用户选定目标；跨端历史交换按 ENH-01/TASK-035 | 取消不产生半份“导出成功”；失败保留原数据 |
| 向其他应用分享附件 | FileProvider `content://` + 临时最小 URI 授权 | 用户明确选择分享动作 | 不输出 `file://`，不暴露整个私有目录 |
| 直接拍照或录音，若被范围表纳入 | 对实际选定的原生 API 评估 CAMERA/RECORD_AUDIO 等权限 | 功能入口；区分委托系统应用与自建采集实现 | 保留文件选择方式；不得为普通附件上传预先请求 |
| 生物识别解锁，若开启 | BiometricPrompt/平台身份认证 | 用户启用安全策略或解锁时 | 提供该策略允许的恢复路径；不能静默改成明文存储 |
| 有限前台服务，若 spike 决定采用 | 对应 FGS 声明、类型及平台要求 | 用户可见的合法操作启动时 | 失败进入有界中断/恢复路径，不改用保活循环 |
| 周期同步与小组件刷新 | WorkManager/小组件更新机制 | 启用相应能力后 | 不请求精确闹钟或忽略电池优化来制造实时保证 |

API 37 的局域网限制覆盖底层连接及常见网络库，不能通过改用 OkHttp、socket 或 WebView 绕开。域名最终解析到内网同样要纳入验证；权限识别不能只靠输入字符串是否以 `192.168` 开头。[S16]

本基线没有广泛存储访问、所有文件管理、定位、联系人或无障碍服务需求。依赖合并后的最终 manifest 必须与权限矩阵逐项核对；依赖引入了额外权限时需解释必要性或移除。

## 5. 凭据、数据库、附件与备份

### 5.1 数据分类与落点

| 数据 | 候选存储 | 导出/备份策略 |
| --- | --- | --- |
| 管理 API key、聊天凭据、监控访问秘密 | SecretStore 加密封装；Keystore 管理加密密钥 | 默认不进入系统云备份、D2D 迁移或普通诊断包 |
| 非秘密偏好、界面设置 | DataStore | 可按明确 allowlist 备份；不得混入 token |
| 聊天正文、草稿、附件索引 | Room；字段范围与 schema 见第五章 | 按第五章的用户数据策略；本地持久化不等于自动上传云端 |
| 附件原件与缩略图 | 应用私有文件，以稳定 ID 引用 | 独立容量和保留策略；临时缓存可清理，原件不能被缓存清理误删 |
| FCM token、安装/endpoint 绑定状态 | 独立设备状态存储 | 不作为跨设备恢复身份；恢复后重新注册并核对服务端绑定 |
| 小组件显示快照 | 明确批准的最小快照存储 | 无凭据、无聊天正文；含来源、采集时间、状态和绑定 ID |
| 日志/诊断 | 结构化、白名单字段、容量上限 | 默认无请求体和秘密；导出前再次脱敏 |

如果需要保存小组件快照，应将其作为独立的数据保留决策记录。不能因小组件需要在进程外展示，就顺便把原本仅限会话缓存的全部额度历史永久落盘。

上述凭据落盘规则适用于用户选择的“记住连接”。`CON-03` 的临时连接必须仅在内存中保留秘密：进程结束后需要重新连接，检查点、备份、Worker 输入和返回栈都不保存该秘密，退后台也不自动升级为持久连接。临时凭据失效时可恢复已有非秘密历史，但需要凭据的后台操作返回“需要重新连接”。记住模式保存失败必须报告失败，不能静默降级为临时模式或反向改变用户选择。

### 5.2 SecretStore 实施要求

Android Keystore 保护的是密码学密钥；它不会自动加密本应用所有文件，也不保证所有设备都提供相同的硬件保护等级。[S11]

候选实现使用平台密码学 API 与 Keystore 生成的 AES-GCM 密钥，不设计私有加密算法。SecretStore 对外暴露保存、读取、更新、删除及健康状态，调用方不接触密钥材料。

- 密文封装至少有 `formatVersion`、`keyAliasVersion`、nonce/IV、密文与认证标签所需的信息；每次加密使用新的安全随机 nonce，不根据账户 ID 或时间戳拼出固定 IV。
- 将不含秘密的身份 ID、凭据用途与封装版本纳入认证附加数据或等效完整性绑定，防止不同用途密文被错误互换。
- 写入采用临时写入与原子提交/受控事务，成功前不覆盖最后一份可读取凭据；内存中保留明文的时间和副本数量尽量短。
- 不将凭据写入 SavedStateHandle、导航 key、WorkManager inputData、Intent extras、通知、剪贴板历史、截图测试夹具或 HTTP body 日志。
- 密钥轮换有新旧版本读取与完成标记；不要先删旧密钥再迁移密文。
- 硬件支持情况只记录非秘密的诊断信息，不将“不支持 StrongBox”一概视作用户无法使用应用。若产品安全策略要求更高保护等级，应作为明确的支持范围决策。
- 每次读取都处理失败类型；不能 `catch` 后返回空字符串并继续发送请求。

`androidx.security:security-crypto` 的 API 已弃用，不能因为看到旧教程就把 EncryptedSharedPreferences 列为新项目默认基础。弃用也不意味着应把秘密改存明文 SharedPreferences。[S12]

### 5.3 应用锁与后台访问必须一致

将“UI 打开前认证”和“密钥每次使用必须重新认证”区分开。若密钥本身要求交互式认证，后台额度刷新、监控注册续期或后台收尾可能不能读取它。产品需在设置页解释实际影响，后台任务遇到需要解锁时返回 `NeedsUserUnlock`，不循环弹出生物识别窗口。

候选默认是保护秘密并支持既定后台能力。本章不把新的应用锁或生物识别界面暗中列为首版必需功能；若未来采用更严格的用户认证设置，先更新范围与任务映射。启用、修改和关闭该设置都要做迁移及恢复测试，不能通过删库让错误消失。

### 5.4 安全存储失败分类

| 领域错误 | 典型情形 | 用户可见结果 | 自动处理边界 |
| --- | --- | --- | --- |
| `SecretMissing` | 首次连接、用户已删除秘密 | 提示重新填写凭据；保留可访问的非秘密配置 | 不自动创建随机替代 token |
| `NeedsUserUnlock` | 当前密钥策略需要用户认证 | 前台提供解锁；后台记录待解锁状态 | 不重试认证弹窗；不改变安全策略 |
| `KeyUnavailable` | 设备/Keystore 暂时不可用 | 明确可重试错误 | 仅有限重试；不回退到明文 |
| `KeyInvalidatedOrLost` | 密钥失效、卸载重装后恢复了密文等 | 对受影响连接重新授权/录入 | 不删除所有聊天或其他账户；不声称旧秘密已恢复 |
| `IntegrityFailure` | 认证标签校验失败、密文或绑定身份不匹配 | 停止使用该秘密并提供安全恢复入口 | 不把损坏密文当空凭据发送；不静默覆盖证据 |
| `UnsupportedSecretVersion` | 数据来自更高版本或未知格式 | 提示版本不兼容 | 不猜解码方式、不降级写回 |
| `StorageUnavailable` | 存储空间不足、权限/I/O 错误 | 保存失败，原有效状态保持 | 不显示“保存成功”；不得悄悄改成仅内存保存 |
| `MigrationIncomplete` | 轮换或升级中断 | 按恢复记录续做或回滚 | 不在未验证新版本可读时清理旧密钥 |

以上是项目领域分类，不要求每类一一对应某个系统 exception。平台适配层映射异常，UI 和业务层消费稳定语义。

### 5.5 备份与恢复的明确规则

Auto Backup 默认覆盖许多应用文件和数据库；Android 12+ 有新的 `dataExtractionRules`，旧系统仍需相应旧格式规则。部分厂商设备间迁移行为不能仅凭 `allowBackup=false` 推断。[S13][S14]

候选默认要求：

1. 对云备份、D2D 和任何实际采用的跨平台传输分别列 allowlist/exclude；凭据密文、设备 token 和设备绑定状态明确排除。
2. 不把系统自动备份当作本项目已获得用户授权的新增云同步功能。聊天和附件是否参与系统备份按第五章单独裁决，默认不因 SDK 默认值而意外上传。
3. 恢复后重新核对设备身份与 endpoint；旧 FCM token 不作为新设备身份使用。
4. 测试“只有密文，没有原 Keystore 密钥”“部分文件恢复”“数据库在、附件不在”“旧格式设置恢复”四类失败。
5. 明确用户主动导出是否包含秘密。普通导出默认不包含；若未来提供含秘密的迁移包，另定义端到端加密、解锁、版本及失窃威胁，不直接输出明文 JSON。

## 6. 网络、内容渲染与附件边界

### 6.1 每个连接都绑定身份与信任策略

连接规范化与请求路径由第四章统一定义。Android 层必须确保 UI 编辑地址、重定向、连接池复用或异步回调不会让一个服务的凭据被发送到另一个服务。

- Release 默认使用 HTTPS、平台证书与主机名验证；错误分为证书链、主机名、过期、网络和认证等可行动类别。[S15]
- 不设置“信任所有证书”，不让 hostname verifier 总返回 true，不在证书错误回调中无条件继续。
- 携带 Authorization 的请求对跨 origin 重定向采用明确拒绝/重新确认策略，不把凭据盲目转发到新主机。重定向后的请求路径、协议降级和端口变化也纳入验证。
- 管理接口、聊天服务、监控后端、附件远程地址使用独立的授权范围；一处配置 API key 不意味着所有网络请求都附带同一个头。
- Debug CA 仅放在 `debug-overrides` 或严格隔离的 debug 配置。Release 产物核验不能只看源文件，需要检查最终 manifest 和网络配置。[S15]
- 用户自建 CA 如需支持，必须按连接范围管理、展示可理解的信任信息并允许撤销；静态域名 XML 无法单独覆盖任意运行时地址的全部需求。
- `CON-01` 的本次基线是 HTTPS。明文 HTTP 不作为未映射的“兼容开关”偷偷加入；若未来明确扩展该能力，另立范围及信任策略决定，禁止隐式降级或全局放开明文。

直接客户端连接私有地址是本产品的实际使用场景，不能简单禁用所有私网来“修复安全”。如果监控后端代用户访问地址，则由第四章定义服务端 SSRF、DNS 重解析与网络边界；客户端 LAN 授权不能替代服务端校验。

### 6.2 错误类别必须能解释真实原因

至少保留 `NetworkUnavailable`、`DnsFailure`、`LocalNetworkPermissionDenied`、`TlsFailure`、`AuthenticationRejected`、`AuthorizationDenied`、`RateLimited`、`Timeout`、`ProtocolMismatch`、`PartialResponse` 和 `Cancelled` 等语义。具体枚举名称与第四章统一。

对额度部分失败，保留成功部分并标记来源与更新时间；未获取的数据不转成 0。对生成请求，超时且结果不明不能自动当作“从未执行”。重试政策按读取、幂等写入和非幂等生成分别制定。

### 6.3 WebView 只允许经审查的局部渲染用途

主体 UI、导航和权限由原生 Compose 实现。Markdown、代码块、表格和公式按 `CHA-17/TASK-017` 提供原生富文本能力。`CHA-18/TASK-020` 的静态 HTML 预览、源码查看及复制是发布必需项，可采用独立隔离的 WebView 实现静态排版；不得将它当成可选增强，或只展示源码便宣称静态预览已完成。其他确需 WebView 的用途先证明原生方案缺口，并隔离为最小渲染组件。

局部 WebView 的最低合同：

- 不直接执行模型输出或用户附件中的任意 JavaScript，不为不可信页面暴露 `addJavascriptInterface` 等原生桥。[S22][S23]
- 静态 HTML 预览本身禁止脚本、外网请求、CSS 外部资源、iframe、弹窗及页面导航；测试含能访问受控测试服务器的正对照，防止测试环境原本断网造成假通过。它不共享聊天或登录组件的凭据、cookie 和 WebView 状态。
- 默认关闭不必要的文件/content 访问与 JavaScript；如受控渲染脚本必须开启，只加载应用控制的代码，内容作为数据进入并经过适当转义。
- 不加载任意 `file://`、`javascript:`、`intent:` 或未经验证的自定义 scheme；链接点击先经过 scheme/origin 检查，再由用户选择的外部浏览方式处理。
- 本地受控资源使用合适的受限资源加载机制；不让远程内容继承应用私有文件访问权。
- 图片 URL 和链接预览不得携带管理凭据，不因一条聊天消息自动加载有追踪意义的任意远程资源；内容加载策略在第五章统一。
- WebView renderer 崩溃、超大内容、无可用 provider 等场景有失败 UI，不影响凭据库和其他工作区。

### 6.4 附件导入与分享

Photo Picker 和 SAF 将访问范围限制到用户选中的内容；持久 URI 授权仍可能因文件删除、移动或 provider 变化失效。[S18][S19][S20]

当前图片附件基线由 `CHA-06` 和第五章界定，至少保留源端最多四张及纯图片提问能力。视频、任意文档上传、录音和跨端历史导入导出不因本节列出安全机制就自动成为首版范围。候选附件流程：选择→读取元数据→限量流式导入→验证类型/尺寸→写入应用私有存储→提交附件索引。若需要可靠跨重启保留原件，应复制到私有存储，不能把外部 URI 永久可读当作唯一保证。

- 仅信任受校验的 ID 和内部生成文件名；显示名称不用于拼接私有文件路径。
- MIME 声明、扩展名与实际内容可以不同；解码器要有大小、像素和时间预算，未知大小的流也必须受限。
- 大文件不先完整读入内存；上传可取消，取消后按第五章清理临时文件和引用。
- 来自系统选择器的内容也按不可信数据处理；不执行脚本、宏、可执行文件或任意 HTML 中的活动内容。
- 通过 FileProvider 分享精确文件和最小临时授权，不开放整个目录；检查导出组件与 intent 处理路径。[S21]
- 导出成功以目标实际写入完成为准；存储不足、provider 离线和用户取消不能被统计成成功。

## 7. 监控、WorkManager、FCM 与无 GMS 能力

### 7.1 三条通路各有用途

| 通路 | 负责什么 | 不能承担什么 |
| --- | --- | --- |
| 前台数据通路 | 用户打开应用时刷新、手动操作、流式聊天 | 进程死亡后的永久在线 |
| WorkManager 补偿通路 | 周期拉取最新状态、短时补偿、允许重复执行的恢复工作 | 秒级周期、精确时刻保证、无限 SSE |
| 后端监控与推送通路 | 后端持续观测、产生事件、向已授权 endpoint 尝试投递 | 保证任何网络/OEM/权限状态下必达，或代替客户端权限 |

周期 WorkManager 的最小间隔为 15 分钟，且受约束与节电策略影响；配置“15 分钟”不意味着每 15 分钟准点执行。Doze 会限制网络及调度，不能用重复 OneTimeWork 链或精确闹钟包装成实时轮询。[S24][S25]

Work 必须按连接/订阅稳定 ID 去重，设置合理网络条件、退避与尝试边界。删除或解绑时按第四章状态机取消对应本机 work，保留结果不明的远端操作和 detached handle 的恢复能力；本机停止调度不等于远端订阅已停止。任务开始、读取秘密前和写回结果前都确认身份版本仍有效。凭据过期、权限拒绝和协议不兼容是需要用户处理或版本处理的状态，不应无限 retry。

### 7.2 通知状态与监控状态独立

至少分别表达以下状态：

- 后端订阅：未配置、活动、终态/过期、服务端拒绝等可解释状态；实际状态枚举与第四章一致，不自行新增远端暂停操作。
- 设备通道：未注册、注册中、可用、token 轮换中、不支持、暂不可达。
- 系统通知：未询问、允许、拒绝、对应 channel 被关闭。
- 最近状态/事件：第四章规定的订阅 ID、revision/sequence、观察时间、已知同步时间与本地展示去重标识；不由此另增服务端历史事件或未读邮箱协议。

通知页不得只用一个绿色“已开启”掩盖其中任一失败。用户拒绝通知后，应用内监控、已经保存的本地信息和服务端可查询的当前快照仍可用；恢复授权后注册/校验通道，不自动回放大量过期通知。事件去重和有效期语义由第四章合同定义，不承诺补回服务端未保留的中间状态。

FCM token 是设备投递地址，不是用户账户、聊天会话或永久订阅身份。轮换、解绑、卸载后的无效 token、服务端退订和事件幂等都属于监控合同。[S28]

### 7.3 有 GMS 与无 GMS 的产品能力表

| 能力 | 兼容 GMS 且 FCM 已配置 | 无 GMS / FCM 不可用 |
| --- | --- | --- |
| 连接、额度、CAP/诊断、前台聊天 | 正常使用 | 正常使用，不要求安装 GMS 才能进入应用 |
| 本地完成通知 | 操作仍可执行且系统允许时可发 | 相同；本地通知不等于 FCM |
| 后端持续监测 | 取决于后端订阅与部署状态 | 相同，监测本身不依赖手机是否有 GMS |
| 远程事件及时提示 | 后端通过 FCM 尽力投递，受权限、网络和系统影响 | 默认不承诺即时推送；应用打开或允许的周期同步时获取当前状态/快照 |
| 状态与快照恢复 | 按第四章读取当前订阅及来源快照，处理 revision/sequence | 相同；不把当前快照读取宣传为历史事件补投递 |
| 小组件快照 | 从本地最近快照呈现 | 相同，标明更新时间；不伪装实时 |
| 厂商推送通道 | 当前不要求 | 若将来加入，另定义支持范围、依赖和维护成本 |

FCM 官方 Android 接入要求兼容的 Google Play 环境；本项目必须运行时检查并允许降级。不得将 Google Analytics 变成基本功能的强制依赖，也不得把 FCM 服务端凭据打包进 APK。[S28]

高优先级推送用于有时效、用户可见的提醒，不用静默高优先级流量替代常驻连接；官方明确可能对不产生用户可见通知的模式降级。[S29]

初版可以采用运行时能力判断，而非立即拆出多套复杂 flavor。若需要一个完全不携带 GMS SDK 的发行包，再依据体积、初始化隐私和发布渠道做明确构建决策，避免隐式自动初始化与用户选择冲突。

## 8. 小组件、锁屏与可见信息最小化

Android 小组件是平台原生承载面，采用 Glance 或经过证明更合适的原生 AppWidget 实现。它读取被批准的最小快照，不能依赖 Activity 内存始终存在。Glance 的状态与更新也需考虑组件被重新实例化和进程内状态丢失。[S30]

小组件共享默认关闭，仅在用户明确开启后生成投影。每个小组件绑定明确的来源及账号/订阅 opaque ID，不跟随一个后来变化的全局“当前账户”静默改绑。共享来源切换时，旧来源的投影立即失效；新来源按显式共享与选择规则重新产生投影，不能继续展示旧数据或自动选中另一个账号。这同时满足“绑定不漂移”和 `WID-01/WID-06` 的切来源清理合同。至少展示数据更新时间、是否过期/错误，以及打开对应页面的动作；权限拒绝、未连接和服务器无数据使用不同状态。未更新不等于额度为零。

默认隐私规则：

- 小组件不显示 API key、完整服务器私有地址、聊天正文或可识别用户的账号信息；额度数值的展示范围由用户在配置时选择。
- 退出账号、解绑或删除连接后，使相关小组件尽快转为未连接状态并清理本地可见快照；不能仅删除凭据而遗留桌面上的旧敏感内容。
- 锁屏通知默认采用 private 或更严格可见性，并提供不含敏感数据的公开版本，例如“有一项监控更新”。用户选择显示详细数值才放宽展示。[S31]
- 通知内容、图标和 PendingIntent 都以最小字段构造；点击后在应用中重新验证身份和对象存在性。不能通过通知 action 绕过需要前台确认的管理写操作。
- 不假定桌面小组件与锁屏小组件的承载能力在所有系统/OEM上一致；宣称支持的承载面分别出证据。
- API 37 对 RemoteViews 图像总内存有更严格约束。小组件以文本和轻量图形为主，尺寸组合、图片降采样和更新失败处理进入 PLAT-S05，不把完整聊天截图或大图塞进组件。[S06]

聊天完成通知和监控告警使用各自稳定 channel，使用户可以分别控制。批量更新合并，不以每个 token 或每次额度读取生成通知。

## 9. 平台等价边界与“完整移植”判定

完整移植按基线能力与用户结果判定，平台 API 不要求同名。每个差异必须有实现、明确的平台等价方案，或被范围决策批准的差异；不能用“Android 限制”四字省略功能。

| iOS 能力类别/产品结果 | Android 候选等价 | 完成证据 |
| --- | --- | --- |
| 五工作区与独立页面路径 | 五独立 Navigation 3 返回栈，自适应单双栏 | 切换/返回/深链/旋转/宽窄变化不串栈 |
| 安全保存连接秘密 | Keystore + SecretStore 的明确密文封装 | 凭据读写、损坏、密钥丢失、轮换、备份恢复与日志检查 |
| 活跃会话跨页面 | 会话 coordinator 与 UI 生命周期分离 | 一次发送只创建一个操作，切页仍可观察 |
| 约 30 秒后台尽力收尾 | 第 3.3 节有界收尾和检查点 | 提前完成、30 秒到期、系统提前中止、回来恢复均有真机证据 |
| 进程结束后的历史恢复 | Room/文件恢复，未结束操作标记 interrupted | 不重复发送、不虚构完成、可查看已保存内容 |
| 监控提醒 | 后端监控 + Android 通知，FCM 为可选通道 | 有 GMS、无 GMS、拒绝授权和 token 轮换均按能力表工作 |
| 系统外信息展示 | 原生通知/小组件展示有来源时间的最小快照 | 刷新、过期、解绑、锁屏隐私与窗口尺寸测试 |
| 图片附件选取、查看及基线内用户动作 | Photo Picker/受控选择器/私有文件；需要分享时使用 FileProvider | URI 失效、超限、取消、低存储和临时授权测试；跨端导出另按 ENH-01 |

约 30 秒有界收尾不依赖新增服务端持久聊天任务。真正“手机被终止后仍持续生成”的能力如果未来要加入，属于超出当前基线的增强，必须单独定义服务端执行、取消、计费、重取结果与数据保留合同。

所有尚缺平台证据的条目保持“待验证”，不能在发布说明中写成已实现、已在 Duo 真机验证或支持所有 Android 厂商。
